## Rules that must not be broken

1. **Contracts first.** `docs/API.md` is the frontend↔backend contract; `docs/DATABASE.md` is the backend↔ML
   contract (exact snake_case columns, PascalCase enum strings). Change the doc in the same change as the code.
2. **Layering.** Controllers stay thin (one service call). Business rules live in Domain/Application. Infrastructure
   only implements Application interfaces. Never expose EF entities from the API — map to DTOs (`Mapping/Mappers.cs`).
3. **Every protected endpoint names a policy** from `Policies`. Frontend guards are cosmetic only.
4. **Safety semantics.** ML output never makes an aircraft dispatchable; never write "safe". Isolation Forest scores
   are not probabilities. `probability` is returned only when `probability_validated` (DB check constraint + mapper).
   Failure prediction stays BLOCKED until the dataset audit reports `failure_prediction_readiness.status = "Ready"`.
   Never fabricate metrics, accuracy or probabilities — in code, UI copy, demo data or docs.
5. **No invented thresholds.** Import validation is physical plausibility only; `engineering_threshold` rows need a
   specification reference and approver.
6. **Secrets.** Never commit passwords, connection strings, signing keys or tokens, and never print them. They live
   in the git-ignored root `.env` (or environment variables). `appsettings.json` keeps empty placeholders.
10. **Database isolation.** Target only `aircraft_predict_db` (`DB_NAME`). Never connect to, migrate, seed or test
    against `aircraft_app`. Disposable test databases must be named `aircraft_predict_db_test_*`.
11. **Reference data** comes from `tools/db/seed/csv` (validate → generate → check → `apply-seed.ps1`); status IDs
    (0 Inactive, 1 Active, 2 Deleted) are stable and mirrored by `LifecycleStatus` — never renumber.
12. **File encoding.** Never edit files via PowerShell 5.1 `Get-Content`/`Set-Content` round-trips (they corrupt UTF-8
    and add BOMs); use the Edit/Write tools. PS 5.1 lacks static `RandomNumberGenerator.GetBytes` — use `Create().GetBytes($b)`.
7. **ML boundary.** Python runs as a separate process; the API only queues `pipeline_run` rows. ML roles must not touch
   users, tokens, audit, work orders or inspection flags; ML may only move models `Trained → Registered`.
   After any migration, re-run `tools\db\apply-migrations.ps1` (re-applies `grant-privileges.sql`).
8. **Tests must stay runnable without PostgreSQL or Docker** (in-memory provider). Provider-specific behaviour goes in
   `PostgresRepositoryTests` (Testcontainers). Avoid raw SQL and `EF.Functions.ILike` in repositories.
9. **Honest reporting.** Do not claim a build, migration, test or integration succeeded unless it was actually run.

## Conventions

* C#: file-scoped namespaces, primary constructors, records for DTOs, async + `CancellationToken` everywhere,
  validation via `Validator`, errors via `AppException` subclasses (mapped to ProblemDetails with a `code`).
* JSON: camelCase, enums as strings, UTC ISO-8601 timestamps. jsonb columns are passed through verbatim
  (so ML-written keys such as `failure_prediction_readiness` stay snake_case).
* Frontend: JavaScript/JSX only. Styling: Tailwind CSS 4 utilities (adopted 2026-10-27 by user decision) on top of the
  existing tokens in `src/styles/tokens.css`, all entered through `src/styles/index.css` (layers theme -> legacy -> utilities,
  no preflight). No UI/chart/router libraries: charts stay hand-rolled SVG (`src/components/charts`).
* Python: parameterised SQL only, all SQL in `repositories.py`; business logic testable with DataFrames + fakes.

### 2026-10-22 (later) — Silver/Gold commit defect fixed (S3A magic committer); readiness recomputed

**Reproduced first**: `spark/jobs/_committer_probe.py` writes a tiny Parquet dataset to a disposable
`s3a://silver/_committer_probe/<id>` prefix. With the default committer it reported `PROBE write = FAILED`,
confirming the defect without touching real data. The probe printed `fs.s3a.committer.name = file` — the
FileOutputCommitter, whose `_temporary` cleanup is exactly the `DeleteObjects` on keys ending in `/` that this
MinIO build refuses.

**Fix — S3A magic committer** (writes straight to final keys as multipart uploads; no `_temporary` at all):
- `spark/Dockerfile` installs `spark-hadoop-cloud_2.13-4.2.0.jar` directly. It supplies `PathOutputCommitProtocol`
  and `BindingParquetOutputCommitter`, is not bundled in the Spark image, and could **not** be added through
  `--packages`: it drags in the whole `hadoop-cloud-storage` tree (aliyun/azure/opentracing) and job start-up
  failed on dependency resolution.
- `spark/run-spark-job.sh` sets `fs.s3a.committer.name=magic`, `committer.magic.enabled`, `committer.generate.uuid`,
  the S3A committer factory, and the two Spark binding classes. Versions verified compatible: Spark 4.2.0 bundles
  hadoop-client 3.5.0, matching `hadoop-aws 3.5.0`.
- `docker-compose.yml` adds an `ivy_cache_2_5_2` volume: Spark 4.2 resolves `--packages` under `.ivy2.5.2`, so the
  existing `.ivy2` cache was never reused and every job start re-downloaded hadoop-aws and the AWS SDK bundle.
- `bronze_to_silver_gold_postgres_stream.py`: `_write_with_retry` (4 attempts, linear backoff, env-tunable). This
  MinIO AIStor **Community License** build intermittently answers 403/503 to individual writes under load — also
  seen once as a 503 on an API upload. Each retry is a full overwrite of that batch's own path, so it cannot

explained individually. Proven read-only by test (`The_dry_run_writes_nothing`) and by before/after row counts

**Defect 1 — severity threshold was an alphabetical string comparison (shipped bug, now fixed).**
Enums persist as PascalCase **strings** (`AppDbContext.ConfigureConventions`), so
`a.Severity >= minimumSeverity` translated to a SQL *string* comparison. `'High' < 'Low' < 'Medium'`
alphabetically, so `>= 'High'` matched **every** severity. The first dry run selected
**12 Low + 11 Medium + 2 High** for a High-only threshold — i.e. the generator would have raised work orders
for Low-severity anomalies. Fixed by comparing against an explicit allowed set
(`Enum.GetValues<AnomalySeverity>().Where(s => s >= minimum)` → `IN (...)`), correct whatever the storage form.
**The EF in-memory provider compares enums ordinally and so could not catch this**; a PostgreSQL-backed
regression test was added to `PostgresRepositoryTests` (`Anomaly_severity_threshold_is_not_an_alphabetical_string_comparison`),
which is where provider-specific behaviour belongs per project rule 8.

**Defect 2 — import deletion was not actually resumable (my own code, found by the UI agent).**
`ImportDeletionService` removed the `TelemetryImport` row inside the transaction *before* attempting object
storage, so after a partial failure the row was already gone and a retried `DELETE` returned **404** instead of
resuming — the API claimed "safe to retry" while being unrecoverable. Reordered: **object storage is cleaned
first**, and the database half only runs once storage is clear. A storage failure now leaves everything intact,
returns `completed=false` with `remainingWork`, and a retry genuinely finishes. Covered by
`A_storage_failure_leaves_the_import_intact_so_the_retry_can_resume` with fault injection in `InMemoryRawStore`.
